# Работа агента в tSearch

Прочитай применимые вложенные `AGENTS.md`, если они есть. Подгружай материалы по задаче:

- Устройство расширения и поиск владельца поведения — [карта проекта](docs/README.md).
- Подготовка окружения, сборка, проверка в браузере или выпуск — [руководство по разработке](docs/development.md).
- Добавление, изменение или ревью тестов — [руководство по проверкам](docs/testing.md).
- Разработка и проверка встроенных трекеров — [локальный скилл](.agents/skills/tracker-maintenance/SKILL.md).
- Сборка Bridge, запросы из открытого Chrome и диагностика соединения — [скилл tsearch-bridge](.agents/skills/tsearch-bridge/SKILL.md).
- Локальные заметки, передача незавершённой работы и экспорты переписок — [агентский контекст](docs/agent-context.md).

## Работа с репозиторием

- Сохраняй чужие незакоммиченные изменения. Создавай коммит только по явному запросу.
- Ограничивай правки областью задачи. Исходники и проверяемые входные данные правь в их исходных каталогах. Сборочные артефакты в `dist/` создаются штатными командами.
- На страницах и в контейнерах используй публичные компоненты tSearch для переиспользуемого интерфейса. Импорты специализированных UI-библиотек, их типы и настройки держи внутри компонентов, которые их подключают. Публичные пропсы этих компонентов описывай типами tSearch, React или HTML.
- При изменении расширения учитывай совместимость сохранённых профилей, настроек и форматов модулей. Для изменений сообщений между страницами, фоновым кодом и sandbox проверяй обе стороны обмена.
- При изменении ExKit следуй [контракту совместимости и проверке модели](docs/exkit.md).
- При работе с правами, сетевыми запросами, вкладками и исполнением модулей проверяй границы доступа. Не расширяй права без требования задачи и не добавляй в репозиторий секреты, cookies, данные аккаунтов или личную историю поиска.
- Пользовательскую документацию держи на уровне назначения, использования и публичных контрактов. Подробности реализации уместны в технической документации по явному запросу. У каждой инструкции должен быть один основной источник.

## Проверка

- Для реальных запросов используй [Chrome стенда](docs/development.md#проверка-в-браузере).
- Выбирай проверку по [наблюдаемому эффекту и значимым рискам](docs/testing.md). Для правок инструкций и документации проверь ссылки, согласованность и область diff.
- Учитывай ограничения текущей задачи на запуск команд. В отчёте укажи выполненные проверки и существенные ограничения.
