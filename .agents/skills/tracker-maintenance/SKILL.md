# Трекеры tSearch

Прочитай [AGENTS.md](../../../AGENTS.md) и [порядок проверки трекеров](../../../docs/development.md#проверка-и-ремонт-трекеров). Для проверки запросов из сохранённой сессии используй [скилл Bridge](../tsearch-bridge/SKILL.md).

1. Найди профиль источника в `src/trackers/` или `external/` и сравни его запрос с фактическим запросом сайта. Проверь путь, метод, параметры, кодировку и конечный адрес ответа. Страница с HTTP 200 может оказаться формой входа, заглушкой или HTML, который заполняется через API. Сверяй структуру ответа, который получает tSearch, с тем, что видно во вкладке.
2. Переиспользуй открытый Chrome с профилем стенда. Открывай сайты по одному и оставляй пользователю ручной вход. Если Chrome показывает выдачу, а запрос из расширения получает проверку Cloudflare, сравни запрос из вкладки и прямой запрос. Капча, единичный сетевой сбой и отключённый DNS в одной сети сами по себе не подтверждают закрытие. Перед сменой домена проверь, что новый адрес действительно отдаёт выдачу того же источника.
3. Для предоставленного HAR выбери ответы поиска и пагинации, а также метаданные запроса, необходимые для воспроизведения. Разбирай оригинал локально и не копируй HAR в репозиторий. Если нужно сохранить тестовый ответ, сократи его до релевантной разметки и замени идентификаторы, токены, логины, ссылки с ключами и другие пользовательские данные.
4. Сохраняй идентификатор рабочего модуля для совместимости с профилями. Предпочитай семантические атрибуты, устойчивую DOM-структуру и адреса ссылок. Избегай переведённых подписей и генерируемых классов. При переходе на следующую страницу сохраняй исходный запрос и фильтры, если сайт теряет или портит их в ссылке. На последней странице не возвращай ссылку на уже пройденную.
5. Проверь наблюдаемые результаты поиска через tSearch. Для живых запросов выбирай обычные поисковые фразы, без названия проекта, агента или внутренних тестовых меток. Проверяй пустую выдачу по обычной фразе, отсутствие результатов по которой видно на сайте. Сравни названия, ссылки и изменённые поля. Укажи отдельно, что проверено по живому ответу и что воспроизведено на сохранённом HTML. При изменении состава или версий встроенных трекеров обнови индекс штатной командой из руководства.

## Формат трекера

- Для внешнего трекера выбирай JSON в первую очередь. Используй поля и преобразования ExKit, которые уже поддерживают выпущенные версии расширения. Из репозитория устанавливаются и автоматически обновляются JSON-профили.
- Если существующих возможностей JSON не хватает, например для вычисления адреса следующей страницы, используй JavaScript в формате UserScript (`.user.js`). Такой профиль подключается вручную через редактор и требует подтверждения исполнения. Держи функции внутри скрипта. См. [инструкцию по подключению](../../../docs/development.md#проверка-и-ремонт-трекеров) и [пример UnionGang](../../../external/uniongang_tv.user.js).
- Для встроенного трекера по возможности держи особую логику в его модуле. Изменения общего формата оценивай по [контракту ExKit](../../../docs/exkit.md).

## Авторизация и пагинация

- Сравни один и тот же запрос через вкладку с сохранённой сессией и с `credentials: 'omit'`. Признак входа ищи в структуре страницы, например в действии выхода или доступности настроек профиля. Подтверди, что в гостевом ответе появляется форма, ссылка входа в том же месте или редирект. Гостевой ответ иногда выглядит как пустая выдача. Проверяй, что профиль различает её и пустой результат авторизованного поиска.
- Сверяй исходный HTML с DOM вкладки. Если ссылки пагинации появляются только после выполнения JavaScript, проверь, отдаёт ли сервер шаблон адреса, текущую страницу и предел. В живой сессии перейди хотя бы на вторую и последнюю страницы. Если сайт привязывает поисковый идентификатор к сессии, получай первую страницу и переходи дальше последовательно. Проверь в tSearch остановку на последней странице.

## Подготовка иконок

- Начинай с официального фавикона, SVG или логотипа. Можно самостоятельно вырезать знак из логотипа, убрать лишние поля и фон, выровнять на прозрачном холсте. Для маленьких иконок оставляй узнаваемый знак без длинных надписей.
- Готовь растр хотя бы вдвое больше максимального размера отображения в интерфейсе. Для 16 CSS-пикселей нужен исходник от 32×32. Увеличение исходника 16×16 не добавляет детализации. Предпочитай более крупный оригинал или вектор.
- Сжимай PNG или WebP без видимой потери качества. Проверяй альфа-канал после сжатия и читаемость в фактическом размере на светлом и тёмном фоне при DPR 1 и 2. Храни итог в репозитории в формате иконок трекеров, чтобы для показа не требовался сетевой запрос.
