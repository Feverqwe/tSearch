# Проверка изменений

Выбирай проверку по поведению, которое может сломаться. `npm test` запускает тесты исходников и проверяет собранный релизный архив. `npm run check` также проверяет типы, линтинг и форматирование. `npm run test:browser` загружает расширение в чистом профиле Chromium и проверяет пользовательские сценарии. Установку браузера и запуск стендов см. в [руководстве по разработке](development.md#проверка-в-браузере).

- Новые тесты и их вспомогательные файлы размещай в `__tests__/` рядом с проверяемыми исходниками.
- Для изменений интерфейса пройди затронутый сценарий в основной странице или панели. При правках состояния проверь сохранение и повторное открытие, если они входят в сценарий.
- Для трекера или модуля витрины предпочитай обезличенный локальный ответ. Проверь значимый результат разбора и случаи вроде пустой выдачи, изменённой разметки или ошибки входа, если они относятся к правке. Доступность внешнего сайта и состояние аккаунта могут меняться независимо от кода.
- Для фоновых запросов, sandbox и обмена сообщениями проверь результат на границе контекстов, включая доступ, ошибку или отмену там, где они существенны.
- Для исправления воспроизводимого бага добавляй регрессионный тест, когда существующая или ручная проверка недостаточна. Такой тест должен падать из-за поломки наблюдаемого поведения. Избегай проверок текста исходников, случайных констант и внутреннего порядка вызовов. В затронутой области заменяй хрупкие проверки проверками поведения, сохраняя полезное покрытие.
- Для агентских файлов достаточно проверки ссылок и инструкций. При изменении настройки памяти проверь первое создание, повторный запуск и сохранность локальной записи.
