# Сборка и проверка расширения

## Подготовка окружения

Установи [nvm](https://github.com/nvm-sh/nvm) и выполни из корня репозитория:

```sh
nvm install
nvm use
npm ci
```

nvm берёт версию Node.js из [`.nvmrc`](../.nvmrc), а `npm ci` устанавливает зависимости по [lockfile](../package-lock.json). После изменения зависимостей обнови lockfile через `npm install` и перепроверь чистую установку.

## Команды

| Команда | Назначение |
| --- | --- |
| `./build.sh` или `npm run build` | Сборка Rspack для разработки с картами исходников. |
| `npm run watch` | Пересборка при изменении исходников. |
| `npm run typecheck` | Проверка TypeScript. |
| `npm run lint` | Проверка TypeScript и TSX через ESLint. |
| `npm run format` | Проверка форматирования исходников и конфигурации через Prettier. |
| `npm run check` | Проверка типов, линтинг, форматирование и запуск `npm test`. |
| `npm run test:browser` | Браузерные проверки распакованного расширения. |
| `npm run storybook` | Локальный стенд компонентов интерфейса. |
| `npm run build-storybook` | Статическая сборка Storybook. |
| `./release.sh` или `npm run release` | Обновление каталогов, production-сборка и упаковка ZIP. |

Для автоисправлений используй `npm run lint:fix` и `npm run format:fix`.

Исходники расширения и встроенных модулей написаны на TypeScript. Сборка сохраняет формат JavaScript-модулей, который загружает расширение.

[Инструменты обучения моделей](../tools/model-training/README.md) запускаются отдельно от сборки расширения.

Распакованное расширение находится в `dist/extension/`, ZIP — в `dist/tms-<версия>.zip` после `npm run release`. В корне архива лежит `manifest.json`. Команда релиза обновляет отслеживаемые [индекс трекеров](../src/trackers.json) и [индекс модулей витрины](../src/explorers.json). После изменения состава или версий модулей обнови соответствующий индекс с помощью `npm run buildTrackersJson` или `npm run buildExplorersJson`.

## Проверка в браузере

1. Используй отдельный профиль свежего Chrome. Минимальная версия указана в [манифесте](../src/manifest.json). Открой `chrome://extensions`, включи режим разработчика и загрузи `dist/extension/` как распакованное расширение.
2. Воспроизведи сценарий через обычную точку входа. После пересборки перезагрузи расширение и заново открой его страницы.
3. При сбое смотри консоль соответствующего контекста. Основная страница, панель, service worker и sandbox имеют собственные консоли.

Для автоматической проверки установи Chromium командой `npx playwright install chromium` и запусти `npm run test:browser`. Playwright создаёт временный профиль и использует тестовые данные. Для отладки с открытым окном запусти `npm run test:browser -- --headed`.

Для проверки реальных запросов запусти `npm run browser:live`. Откроется установленный Google Chrome с отдельным профилем `.tsearch-test-profile/`, который исключён из Git. При первом запуске загрузи сборку `dist/extension/` через `chrome://extensions`. Там же можно установить [Bridge](../test/bridge/README.md) и другие расширения для проверки. Chrome сохраняет установки и сессии сайтов в этом профиле.

Чтобы открыть сайт сразу после сборки, передай адрес: `npm run browser:live -- https://www.kinopoisk.ru/`. Для новой вкладки без пересборки используй `node test/live/open.ts https://www.kinopoisk.ru/`. Войди вручную в тестовую учётную запись и оставь окно открытым, если нужно проверить другие сайты. На Linux и Windows нестандартный путь к Chrome можно указать в `TSEARCH_CHROME_PATH`.

Команда `npm run test:browser:live` проверяет витрину на реальных сайтах с тем же профилем и запускает собственный экземпляр установленного Google Chrome. Перед ней закрой открытое окно стенда (на macOS — ⌘Q). Выбрать один раздел можно через `-- --grep imdbPopular`. Для проверки «Избранного» войди в тестовую учётную запись, выбери в настройках tSearch непустую папку и запусти `TSEARCH_CHECK_KP_FAVORITES=1 npm run test:browser:live -- --grep 'signed-in Kinopoisk'`. Живые проверки запускаются отдельно от CI и зависят от доступности сайтов.

### Проверка и ремонт трекеров

Для ручного подключения JavaScript-трекера открой редактор трекера из профиля, выбери файл `.user.js` или вставь код и подтверди его сохранение. В метаданных укажи `@trackerURL` с адресом сайта. Скрипт может использовать существующие обработчики ExKit. Пример пагинации есть в [скрипте UnionGang](../external/uniongang_tv.user.js).

Проверяй по одному источнику. Открой сайт трекера в браузере стенда. Если сайт требует входа, оставь вкладку пользователю для ручной авторизации. После входа проверь на сайте запрос с известной выдачей и повтори его в tSearch с выбранным трекером.

Если запрос или разметка сайта изменились, поправь описание в [исходниках трекеров](../src/trackers/) и обнови индекс командой `npm run buildTrackersJson`, когда меняется состав или версия модулей. Пересобери расширение, перезагрузи tSearch в `chrome://extensions` и открой его страницу заново. Окно Chromium можно оставить открытым. Сравни с сайтом фактические результаты tSearch, включая ссылки и переход на следующую страницу, если он есть. Если сайт недоступен или требует учётной записи, зафиксируй, на каком шаге остановилась проверка.

Выбирай селекторы по устойчивой структуре страницы, атрибутам и адресам ссылок. Избегай переводимых подписей, генерируемых классов и классов, зависящих от состояния или оформления. Для пагинации проверь начало выдачи и последнюю страницу, где ссылки на предыдущие страницы могут оставаться видимыми.

[Bridge](../test/bridge/README.md) позволяет проверить тело ответа из Jest через открытую вкладку сайта. Проверку запроса дополняй поиском в tSearch, чтобы подтвердить разбор выдачи. Если сайт открывается вручную, а прямой запрос tSearch получает проверку Cloudflare, попробуй опцию «Включить поддержку прокси» в настройках этого трекера в профиле. Она выполняет запрос через вкладку сайта. Для регрессионной проверки используй обезличенный ответ сайта, если он нужен для воспроизведения ошибки.

## Storybook

Запусти `npm run storybook` и открой адрес, который напечатает команда. Компоненты работают с тестовыми данными и подменой локализации Chrome. Статическая сборка появляется в `storybook-static/`.
